## 2. 来源晋升与维护机制 (Promotion & Lifecycle Protocol)

为了保持代码仓库清洁并支持长效演进，确立以下四层流转规则：

```
           [动态探索 Source Discovery]
                     │
                     ▼
           [本地候选池 .data/sources.json (discovered)]
                     │
                     ▼ 经 Agent/运行验证具备持续有效性
           [种子库晋升 config/sources.seed.json (active)]
                     │
                     ▼ 长期失效/结构变更
           [本地降级 .data/sources.json (degraded)]
                     │
                     ▼ 经长期证据确认永久下线
           [从 seed 归档移除]
```

1. **动态探索入库**：每次 Agent Run 发现的新渠道，先写入本地忽略的 `.data/sources.json`（标记为 `discovered`）；
2. **种子库晋升标准 (Promotion to Seed)**：
   - 渠道具备持续稳定的第一方或高价值聚合发布能力；
   - 经至少一次实际抓取与内容切片验证，且能提供清晰的 Requirement Evidence；
   - 不依赖短期偶发个人凭据或违法爬取手段。
3. **本地降级与熔断 (Local Degradation)**：
   - 遭遇源站改版、永久 404 或连续反爬拦截时，在本地 `.data/sources.json` 标记为 `degraded`，避免持续浪费查询预算；
4. **代码库解耦**：所有频繁变化的运行时指标（`last_checked`、`failure_count` 等）仅保存在本地 `.data/sources.json`，严禁提交至 Git 仓库。
