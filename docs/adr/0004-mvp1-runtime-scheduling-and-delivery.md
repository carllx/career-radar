# 4. MVP-1 运行环境、调度模式、本地存储与报告交付形态

日期: 2026-08-15

## 状态

已通过 (Accepted)

## 上下文与问题陈述

在 Career Radar MVP-1 启动阶段，核心目标是“快速跑通、随时可用、安全私密”。系统需要确定：
1. **执行入口与调度模式**：如何在不引入复杂服务器运维与云端基础设施的前提下，实现随时手动触发与日常自动化巡检；
2. **数据隔离与隐私安全**：在公开开源仓库（Public Repo）红线下，如何妥善存放个人真实画像（Profile）、抓取缓存与历史实体状态；
3. **成果交付与交互形态**：Agent 完成巡检与研判后，如何以最高信噪比向用户呈现新机会、重要更新与待确认事项。

## 决策

我们决定确立 **IDE 原生驱动、本地文件系统持久化与 Markdown 结构化简报交付** 的极简轻量架构：

### 1. 运行环境与调度形态

1. **手动即时触发 (Manual On-Demand)**：
   - 作为 IDE 内置 Agent Skill 或专用 Prompt 指令，支持用户随时在对话窗口输入指令一键唤醒并执行全流程巡检。
2. **周期自动化调度 (Scheduled Periodic Run)**：
   - 利用 IDE 原生 `schedule`（Cron 调度）机制实现定时无人值守唤醒（如每日早晨定时触发巡检任务）；
   - Scheduler 仅作为外部无状态唤醒器，不承载任何业务逻辑。
3. **零额外基础设施负担**：
   - MVP-1 暂不引入独立常驻守护进程、云服务器（VPS）或重型 CI/CD 流程，所有工作流依托本地 IDE Agent 环境完成。

### 2. 本地数据拓扑与隐私安全隔离 (Zero PII & Zero Secrets)

1. **仓库公开模板与示例 (Public Templates)**：
   - `profile.example.yaml`：个人画像配置模板（脱敏的学历、专业、赛道偏好、地域等级、硬性排除条件）；
   - `sources.example.json`：初始已知渠道列表与抓取特征模板。
2. **本地私密持久化 (Local Ignored Storage)**：
   - 真实个人配置：`profile.local.yaml`（受 `.gitignore` 保护，严禁提交）；
   - 实体状态与缓存目录：`.data/`（受 `.gitignore` 保护）：
     - `.data/opportunities.jsonl`：全局 Opportunity 实体历史库及最新评估结论；
     - `.data/sources.json`：渠道网络元数据（包含动态探索发现与健康状态）；
     - `.data/announcements/`：原始公告文本与附件切片缓存。

### 3. 报告交付与交互呈现形态

每次 Agent Run 完成后，通过双层形态交付结果：
1. **本地 Markdown 结构化日报 (Daily Digest Report)**：
   - 输出至本地报告目录 `reports/YYYY-MM-DD.md`（高信噪比排版）：
     - 🎯 **强烈推荐 / 高价值新增机会**（职位名称、单位、地点、赛道、离散匹配结论与 Requirement Evidence 原文引用及官方链接）；
     - 🔄 **重点岗位动态变更**（延期通知、附件要求修订、招聘人数变化等变更 Diff）；
     - ⚠️ **需要人工裁决 / 边缘存疑机会 (Uncertain)**（列出具体存疑点与直达链接供人工快速决策）；
     - 🌐 **渠道网络变动 (Source Network Update)**（新增发现渠道、失效/降级源提示）；
2. **IDE 交互回显 (In-chat Summary & Artifact)**：
   - 在 IDE 对话中直接输出高浓度精简摘要与交互式 Artifact，使用户无需跳出开发环境即可完成日常机会审阅。

## 后果与权衡

### 积极影响
- **零运维极速就绪**：无需购买/配置服务器，即刻具备本地随时运行与定时巡检能力；
- **绝对隐私安全**：敏感个人信息与真实数据完全留在本地机器，公开仓库仅保留纯代码与脱敏模板；
- **交付极简直观**：Markdown 本地报告支持长期离线归档与跨端查看，IDE 对话回显保障高效交互。

### 潜在代价
- 定时调度依赖本地机器与 IDE 的唤醒状态；后续若需 7x24 小时云端离线运行，可在 MVP 验证通过后作为演进方向。
